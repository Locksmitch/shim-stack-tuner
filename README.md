# Valving Toolbox

[![CI](https://github.com/Locksmitch/shim-stack-tuner/actions/workflows/ci.yml/badge.svg)](https://github.com/Locksmitch/shim-stack-tuner/actions/workflows/ci.yml)

A small collection of independent, offline calculators for suspension valving and spring setup, consolidated onto one page with a shared light/dark theme. Started as the standalone Shim Stack Tuner (the repo/package name), which is still the flagship tool and now the single page every other tool lives on as its own collapsible section.

## Tools

All of the below live as sections on **[shim-stack-tuner.html](shim-stack-tuner.html)** — collapse/reorder each one independently, same as any other panel.

- **Shim Stack Tuner** (workspace + geometry + advanced panels) — models a shim stack's engagement and float behavior, estimates damping force over a velocity range, and supports target curves and optimizer-style suggestions against a real shim catalog. Its port-geometry fields (r.port/d.port/w.port) can also be estimated from an uploaded photo: click 3 points on the valve's outer edge to set the scale, then trace freeform outlines (any shape — sharp, rounded, kidney) around one or more ports, averaging across however many you trace. Every click snaps to the nearest real edge in the photo automatically (a local Sobel gradient search), so clicks don't need to be pixel-perfect.
- **Oil Viscosity Comparison** — plot two oils (any two calibration points each, not just cSt@40°C/@100°C) side by side, compute Viscosity Index (ASTM D2270/ISO 2909), and pick which one is actually driving the damping-force calculation via a checkbox on its card.
- **Spring Curve Calculator** — compares dual springs-in-series against single springs: spring rate, coil-bind travel, sag/peak force, and a live force-vs-displacement chart with a pop-out view.
- **Shim Delta Tool** — pick two stock tunes and see exactly which shims to remove, keep, and add to go from one to the other.
- **Wheel Force Curve** — plots spring force across a chosen travel range, plus a second line showing spring force plus the additive damper force the current valve tune generates at a chosen shaft velocity (0-8000 mm/s, via a slider). Reads the same in-page state the workspace above just computed — no separate tab, no export/import step.

[index.html](index.html) is a hub/landing page describing each section with a deep link into it. Everything runs entirely in the browser with no install, no accounts, and no network requests.

### Pop-out windows

Four visuals — the shim stack bending preview, the force-vs-velocity chart, the oil viscosity comparison chart, and the shim adjustment table — can each be popped into their own real, separate browser window ("⛶ Pop out" button next to each one) instead of an in-page overlay. A pop-out is a live, read-only mirror: editing anything on the main page (shim rows, geometry, which oil card is active, the target curve) redraws the pop-out immediately, with no export/import step and no manual refresh. Re-clicking a "Pop out" button focuses the existing window instead of opening a duplicate. Closing the main tab doesn't auto-close a pop-out, but with nothing left broadcasting to it, it just stops updating.

## Structure

- [theme.css](theme.css) / [theme.js](theme.js) — shared CSS variables (light + dark palettes), the top nav bar, and the theme-toggle button used by every page. Each tool's own stylesheet references these variables rather than hardcoding colors, so the toggle applies site-wide; state persists via `localStorage`.
- **Shim Stack Tuner**: markup in [shim-stack-tuner.html](shim-stack-tuner.html), styles in [styles.css](styles.css). Logic lives in [app.js](app.js) (event wiring, UI state, orchestration) plus a set of ES modules under [js/](js/): `units.js` (unit conversion), `physics.js` (the calculation engine, including `waltherViscAt()` — a general two-point Walther/ASTM D341 viscosity-temperature interpolation, not fixed to 40°C/100°C), `oil-viscosity-calc.js` (Viscosity Index/SUS math built on top of `waltherViscAt()`), `storage.js` (localStorage helpers), `catalog-data.js` (loads the product/valve/tune catalog and derives the parts bin from it — see below), `oil-data.js` (loads the known-oil viscosity presets — see below), `canvas-utils.js` (shared canvas drawing helpers), and `photo-measure.js` (pure geometry + a small local edge-detection routine for the photo-assisted port measurement: fitting a circle through 3 clicked points, computing r.port/d.port/w.port from a freeform traced outline of any shape, and a Sobel-gradient edge-snap that corrects an imprecise click onto the nearest real boundary in the photo). The page's Oil viscosity comparison panel holds two independent oil cards (name + two calibration points each); a checkbox on each picks which one is "active" — that's the exact fluid `readFluid()` hands to the damping-force solver, so the comparison chart and the force calc are never out of sync. Its live-preview, force-curve, and oil-viscosity canvases (`stackCanvas`, `forceCanvas`, `oilChart`) redraw with theme-aware colors on toggle (see `themeColor()`/`isDarkTheme()` in `canvas-utils.js`); the port-face and photo-measurement canvases still assume a light background, since they draw hand-colored diagram/photo content rather than plotted data. On every successful calculation, `runCalc()` also writes the full current stack (geometry, active oil, valve type, shim rows) to the `sst_live_config_v1` localStorage key — a one-way snapshot that the Wheel Force Curve page reads, so it always reflects whatever the tuner last successfully computed without any explicit export/import step. The tuner itself also reads this same key on load (`applyConfigToUI()` in `init()`) and restores it instead of the built-in demo stack, so reopening the page picks up wherever you left off; the "Load example" button resets back to the demo stack on demand (and, since that's itself a successful calc, becomes the new "last used" state until you change something else).
- **Catalog data store**: the stock product/valve/tune library (currently FOX's 2025 38 Factory Grip X2 and RockShox's 2025 Vivid Coil) lives in [data/catalog.json](data/catalog.json), not in JS. A product's dimensions are always stored canonically in inches; a metric-sourced product (like the Vivid Coil) adds a `"units": "mm"` hint so the catalog/tune UI displays native mm instead of odd inch decimals, and so its thicknesses skip FOX's `.0031`/`.0032` rounding-noise snap (see `canonThk` in `catalog-data.js`), which would otherwise lightly corrupt an exact mm→in conversion. Tune rows also carry an optional 4th element, `"deltaT"`, marking a delta/triangle shim (see `deltaCoverage` in `physics.js`) — a part that reaches the quoted OD via three lobes rather than a full disc, so it's far softer at the rim; the optimizer treats round and delta shims at the same OD as distinct parts. `catalog-data.js`'s `loadCatalog()` fetches it on page load and populates `PRODUCTS`/`PARTS_BIN`; `app.js`'s `init()` awaits that before wiring up the product/valve/tune selects. If the fetch fails (e.g. the file is missing, or the page was opened as `file://` instead of through a server), a status line above the product select reports it and the stock-catalog features are unavailable for that session, but building a stack by hand still works normally. Keeping the data in its own JSON file rather than baked into a JS module means it can be edited (or generated) independently of the code, and is the natural seam for later swapping in a real backend — `loadCatalog(url)` takes the fetch URL as its only parameter, so pointing it at an API route instead of a static file wouldn't require any change to the code that consumes the catalog.
- **Oil data store**: known suspension-fluid viscosity presets (currently Red Line's 1/2.5/5/10/30wt line, Motorex's 2.5/4/5/7.5/10/15W line, and Maxima's PLUSH 3/5/7/10WT line — cSt@40°C/@100°C and VI taken straight from each product's own manufacturer datasheet) live in [data/oils.json](data/oils.json), same reasoning as the catalog above. `js/oil-data.js`'s `loadOils()` fetches it for both oil cards' preset pickers.
- **Spring Curve Calculator, Shim Delta Tool, Wheel Force Curve**: each was originally its own self-contained HTML file, now merged directly into `shim-stack-tuner.html` as its own panel (`#p-spring-calc`, `#p-shim-delta`, `#p-wheel-force`), each wrapping the tool's original markup and its own `<script type="module">` block for zero global-scope collision with `app.js` or each other; their CSS was scoped with an ID-prefix (`#tool-spring-calc .foo`, etc.) and appended to `styles.css`. The Wheel Force Curve's script imports `buildStack`/`solveForceAtVelocity` directly from `js/physics.js` (and `lsGet` from `js/storage.js`) rather than reimplementing that math — it's the one merged tool that depends on the tuner's own modules, since it needs the actual damping-force solver, not just its own arithmetic. It reads the same `sst_live_config_v1` snapshot `runCalc()` writes on every calc, and re-renders on the spot via a same-page `sst-live-config-changed` custom event `app.js` dispatches right after writing that snapshot (the native `storage` event only fires in other tabs, which no longer applies now that it's on the same page).
- **Pop-out windows**: [js/live-sync.js](js/live-sync.js) is a thin pub/sub wrapper around `BroadcastChannel('sst-live-visuals')`. `app.js`'s four visual-drawing functions (`drawStackAtSlider`, `drawForceCurve`, `drawOilChart`, and `runCalc`'s shim-row snapshot) each call `broadcastLiveVisuals({stack: {...}})` (etc.) with exactly the arguments their own `js/*-visual.js` drawing function needs, right after drawing themselves; `broadcastLiveVisuals` merges that slice into the last snapshot, persists it to the `sst_live_visuals_v1` localStorage key, and posts it on the channel. [popout-stack.html](popout-stack.html), [popout-force.html](popout-force.html), [popout-oil.html](popout-oil.html), and [popout-shims.html](popout-shims.html) are minimal pages that import the matching drawing function directly, paint once from `readLiveVisualsSnapshot()` on load (so they're never blank), then redraw on every `subscribeLiveVisuals()` message — no editing, no state of their own. `hiddenCurves` (a `Set`) is the one piece of force-curve state that doesn't survive the JSON round-trip through localStorage; it crosses the wire as a plain array and gets rebuilt into a `Set` on the pop-out side before drawing. Each pop-out also listens for the native `storage` event on `sst_theme` — genuinely cross-window here, unlike the same-page case above — to stay in sync if you toggle the theme while it's open. `app.js`'s `openPopout()` keeps a tracked reference per pop-out key so re-clicking a "Pop out" button focuses the existing window instead of opening a duplicate.

## Testing

`npm test` runs two suites:

- **Unit tests** ([test/physics.test.mjs](test/physics.test.mjs), [test/photo-measure.test.mjs](test/photo-measure.test.mjs)) — exercise `js/physics.js` (the calculation engine) and `js/photo-measure.js` (the photo-measurement geometry) directly with Node's built-in test runner, no browser needed. Run alone: `npm run test:unit`.
- **Smoke test** ([test/smoke.js](test/smoke.js)) — loads the merged page (plus the hub, `index.html`) in a headless browser and checks each starts up without JS errors, plus one representative interaction per section: the shim stack tuner's fuller interaction suite, including its oil viscosity comparison panel's click-to-probe and active-oil switching, plus a full photo-measurement pass against a synthetically generated valve image with known geometry; the spring calculator's pop-out chart; the delta tool's default comparison; the wheel force section's tuner-sync + velocity-slider check; and all 4 site-wide pop-out windows, using Playwright's `page.waitForEvent('page')` to confirm each "Pop out" button opens a real separate window that paints on open (checked by sampling distinct canvas pixel colors — a chart that only cleared to background paints exactly 1) and stays live-synced after an edit on the main page. Run alone: `npm run test:e2e`. One-time setup: `npm install` then `npx playwright install chromium`.
